# CatchEvent

A small Flutter app for discovering and managing campus events. Students browse,
search, save and register for events; organizers create events and see who signed
up. Backed entirely by Firebase Authentication and Cloud Firestore, on the free
Spark plan.

---

## Features

### Students

- Browse upcoming events on the Home tab
- Search by title as you type (case-insensitive)
- Filter by category: Technology, Academic, Sports, Career, Workshop, Social,
  Club, Other
- View full event details (description, schedule, location, organizer,
  capacity, live registration count)
- Save/unsave events (bookmarks are independent of registration)
- Register and unregister, with duplicate registration and over-capacity
  registration rejected
- View saved events and registered events (Upcoming / Past)
- View profile and sign out

### Organizers

- Create events with an image URL, schedule, location and capacity
- Edit and delete only their own events
- See the student list for each of their events
- View all of their events on one screen

### Both

- Email/password sign-up and sign-in with a Student/Organizer role chosen at
  registration
- Session restore on launch, routed by role
- Profile screen with role-appropriate counters and sign out

## Tech stack

| Layer | Choice |
| --- | --- |
| UI | Flutter, Dart, Material 3 |
| State management | `provider` (ChangeNotifier + ProxyProvider) |
| Auth | Firebase Authentication (email/password) |
| Database | Cloud Firestore |
| Formatting | `intl` |

No Firebase Storage or `image_picker`: event images are pasted as URLs, so the
free Spark plan is enough.

```text
lib/
├── main.dart                 App entry: Firebase init, theme, providers, auth gate
├── firebase_options.dart     Generated by `flutterfire configure` (placeholder in repo)
├── models/                   Plain data classes mapping Firestore documents
│   ├── user_model.dart
│   ├── event_model.dart
│   └── registration_model.dart
├── providers/                UI state and Firestore subscriptions
│   ├── auth_provider.dart
│   ├── event_provider.dart
│   └── registration_provider.dart
├── services/                 All Firebase access lives here
│   ├── auth_service.dart
│   ├── event_service.dart
│   └── registration_service.dart
├── screens/
│   ├── auth/                 login_screen, register_screen
│   ├── student/              home, event details, saved events, my events
│   ├── organizer/            home, create/edit event, registrations
│   └── profile_screen.dart   Shared by both roles
├── widgets/                  Shared UI (event card, form, image, list, inputs)
└── utils/                    constants, validators, app_exception
```

The dependency direction is one-way: `screens` → `providers` → `services` →
Firestore. Widgets never touch Firebase directly.

## Getting started

### Prerequisites

- Flutter (stable channel) with Dart SDK `^3.12.2`
- An Android emulator or a device with USB debugging enabled
- A Firebase project (free Spark plan)

On Windows, two one-time SDK prerequisites are also needed — both are explained
in detail in [`FIREBASE_SETUP.md`](FIREBASE_SETUP.md) (Step 0):

1. **Developer Mode** enabled (`start ms-settings:developers`) — Flutter plugin
   builds require symlink support.
2. **CMake 3.22.1** installed via Android Studio's SDK Manager — Gradle
   configures an empty CMake stub even though CatchEvent has no native code.

### Setup

1. **Create the Firebase project** and enable:
   - Authentication → Email/Password
   - Firestore Database (production mode; any region)
2. **Connect the app:**

   ```sh
   dart pub global activate flutterfire_cli
   flutterfire configure
   ```

   Choose your project, select **android** only, and use the application id
   `com.example.catchevent`. This generates `lib/firebase_options.dart` and
   `android/app/google-services.json`.
3. **Publish the security rules** — paste [`firestore.rules`](firestore.rules)
   into Firestore → Rules → Publish, or run:

   ```sh
   firebase login
   firebase use --add
   firebase deploy --only firestore:rules
   ```

4. **Install dependencies and run:**

   ```sh
   flutter pub get
   flutter run
   ```

Until step 2 is done, the app deliberately shows a "Firebase is not configured
yet" screen instead of crashing.

The full walkthrough, including a first-run demo script and a troubleshooting
table, is in [`FIREBASE_SETUP.md`](FIREBASE_SETUP.md).

## Firestore data model

Firestore creates collections on first write; nothing needs to be made by hand.

| Collection | Document id | Fields |
| --- | --- | --- |
| `users` | auth `uid` | `name`, `email`, `role`, `createdAt` |
| `events` | auto id | `title`, `description`, `category`, `imageUrl`, `organizerId`, `organizerName`, `date` (`yyyy-MM-dd`), `startTime` (`HH:mm`), `endTime`, `location`, `capacity`, `registeredCount`, `createdAt` |
| `registrations` | `{eventId}_{studentId}` | `eventId`, `studentId`, `studentName`, `studentEmail`, `createdAt` |
| `savedEvents` | `{userId}_{eventId}` | `userId`, `eventId`, `createdAt` |

Two design points make the data simple to query:

- **Deterministic join ids.** Registering or bookmarking twice is the same write
  rather than a duplicate row, and a join document can be read by reference
  inside a transaction.
- **`registeredCount` on the event.** Firestore transactions cannot run a
  query, only read a document, so the running total lives on the event. It is
  what lets the app check capacity and take a seat atomically. It is excluded
  from `EventModel.toMap()`, so editing an event can never overwrite it.

No composite indexes are required — no query combines an equality filter with
an `orderBy` on a different field, and small result sets are sorted in Dart.

### Security rules

[`firestore.rules`](firestore.rules) enforces the same invariants server-side
that the UI enforces locally:

- signed-in users only
- organizers can create events, and edit or delete only their own
- students may change only `registeredCount`, by exactly one, and never past
  capacity
- students can create and cancel only their own registrations
- bookmarks are private to their owner

## Testing

```sh
flutter analyze
flutter test
```

The test suite covers the parts that need no Firebase connection: form
validators, the event model's seat arithmetic and date formatting, and the
empty-state widget. Screens read from Firestore through the providers and would
need a live backend or a fake to test, so they are not covered.
